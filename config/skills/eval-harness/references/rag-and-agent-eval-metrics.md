# RAG & Agent Evaluation Metrics (The Formal Mathematics)

> **Pattern Origin**: Absorbed from `confident-ai/deepeval` under the Antigravity Autonomous Engineering System (§8 External Proposal Protocol).  
> **Purpose**: Mathematical formulation, programmatic assertion thresholds, and evaluation protocols for evaluating RAG pipelines, LLM outputs, and multi-turn agent systems.

---

## 1. The RAG Triad Metrics

The RAG Triad evaluates the three fundamental interfaces of Retrieval-Augmented Generation:
$$\text{Query} \overset{\text{Answer Relevancy}}{\longleftrightarrow} \text{Actual Output} \overset{\text{Faithfulness}}{\longleftrightarrow} \text{Retrieval Context} \overset{\text{Contextual Precision/Recall}}{\longleftrightarrow} \text{Ground Truth}$$

### A. Faithfulness Metric (Hallucination Detection)
- **Definition**: The proportion of factual claims in the generated `actual_output` that can be directly inferred from or supported by the `retrieval_context`.
- **Mathematical Formula**:
  $$\text{Faithfulness} = \frac{|\text{Truthful Claims Inferred from Context}|}{|\text{Total Claims in Actual Output}|}$$
- **Algorithm**:
  1. Extract all atomic factual assertions $C = \{c_1, c_2, \dots, c_n\}$ from `actual_output`.
  2. For each claim $c_i$, evaluate via NLI (Natural Language Inference) whether `retrieval_context` entails $c_i$.
  3. Return the ratio of entailed claims. Flag any hallucinated claims ($c_i \notin \text{Context}$).
- **Production Threshold**: Pass if $\text{Faithfulness} \ge 0.85$.

---

### B. Answer Relevancy Metric
- **Definition**: Measures how directly the generated `actual_output` addresses the user's `input` prompt, penalizing rambling, incomplete, or off-topic responses.
- **Mathematical Formula**:
  $$\text{Answer Relevancy} = \frac{1}{N} \sum_{i=1}^{N} \cos\left(E(q), E(q_i')\right)$$
  Where:
  - $E(\cdot)$ is a dense embedding function.
  - $q$ is the original user input query.
  - $q_i'$ are $N$ distinct reverse-engineered questions generated by an LLM prompted solely with `actual_output`.
- **Production Threshold**: Pass if $\text{Answer Relevancy} \ge 0.70$.

---

### C. Contextual Precision Metric
- **Definition**: Measures whether the retrieval pipeline ranked relevant chunks higher than irrelevant chunks in the `retrieval_context`.
- **Mathematical Formula**:
  $$\text{Contextual Precision} = \frac{\sum_{k=1}^{K} \left(P@k \times \mathbb{I}_k\right)}{|\text{Total Relevant Chunks in Context}|}$$
  Where:
  - $K$ is the total number of retrieved chunks.
  - $P@k = \frac{\text{Number of relevant chunks in top } k}{k}$.
  - $\mathbb{I}_k \in \{0, 1\}$ is an indicator function denoting whether chunk $k$ is relevant to `ground_truth`.
- **Production Threshold**: Pass if $\text{Contextual Precision} \ge 0.75$.

---

### D. Contextual Recall Metric
- **Definition**: Measures whether all factual statements present in the `ground_truth` are represented within the `retrieval_context`.
- **Mathematical Formula**:
  $$\text{Contextual Recall} = \frac{|\text{Ground Truth Sentences Attributable to Retrieved Context}|}{|\text{Total Sentences in Ground Truth}|}$$
- **Production Threshold**: Pass if $\text{Contextual Recall} \ge 0.80$.

## 2. G-Eval: Deep Model-Based Evaluator Framework

G-Eval uses large language models with Chain-of-Thought (CoT) reasoning to evaluate subjective or complex criteria (e.g., tone, code readability, safety, reasoning depth).

### A. The 4-Step G-Eval Algorithm
1. **Define Task & Rubric**: Provide criteria description and a 1–5 scoring scale with clear anchors.
2. **Generate Evaluation Steps**: Instruct the model to formulate explicit Chain-of-Thought evaluation steps.
3. **CoT Reasoning**: The judge generates step-by-step reasoning evaluating the candidate output against the steps.
4. **Probability-Weighted Scoring**:
   Instead of parsing raw generated numbers (which suffer from token bias), score via token log-probabilities over the score tokens $s \in \{1, 2, 3, 4, 5\}$:
   $$\text{Score} = \sum_{s=1}^{5} s \cdot \frac{P(\text{token} = s)}{\sum_{j=1}^{5} P(\text{token} = j)}$$

## 3. Agent Tool Call Correctness Metric

Evaluates agent tool execution against expected schema and invocation intent:
1. **Tool Selection Accuracy**:
   $$\text{Tool Accuracy} = \frac{|\text{Tools Correctly Invoked} \cap \text{Expected Tools}|}{|\text{Expected Tools}|}$$
2. **Parameter Validity Rate**:
   Percentage of tool arguments satisfying strict schema validation (Pydantic / Zod) without runtime exceptions.
3. **Prohibition of Redundant Retries**:
   An agent trial fails immediately if it makes $\ge 3$ consecutive calls with identical arguments without forward state progression.

## 4. Lexical-First Retrieval Hierarchy (The "Grep-Over-Embeddings" Invariant)

> **Pattern Origin**: Absorbed from PwC Labs (*"Is Grep All You Need? How Agent Harnesses Reshape Agentic Search"*, arXiv:2605.15184).

Mathematical and architectural grounding proving that exact lexical search outperforms dense vector embeddings in agentic codebases:

### A. The Semantic Drift & False Friends Penalty
In codebases and multi-turn agent harnesses, dense vector search incurs severe accuracy penalties due to **Topical Distractors ("False Friends")**:
- Cosine similarity between embeddings groups conceptually related but factually wrong identifiers (e.g., matching `loginUser` when searching for `handleAuthCallback`).
- Lexical matching (`grep` / ripgrep) provides deterministic precision:
  $$\text{Precision}_{\text{lexical}} = \frac{|\text{Exact Regex Hits}|}{|\text{Total Matches}|} = 1.0$$
- Frontier LLMs perform superior semantic synthesis over raw exact matches, making embedding models redundant for code search.

### B. Dual-Axis Delivery Architecture
How search results are presented to the agent context is as critical as the search algorithm itself:
1. **Inline Delivery ($\le 50$ lines)**:
   - When exact grep matches yield concise results ($< 50$ lines), inject directly into the conversation turn context.
2. **Programmatic / File-Based Delivery ($> 50$ lines)**:
   - When matches exceed 50 lines, pipe output to `<conversationId>/scratch/search_results.txt`.
   - Inspect via bounded window reads (`StartLine`/`EndLine`) to prevent context saturation and preserve the $\text{SNR} \ge 20\%$ threshold.

### C. Noise Scaling Invariance
- As background conversation history and extraneous workspace files scale, vector retrieval accuracy decays exponentially due to background noise interference.
- Lexical regex accuracy remains **invariant** to noise scaling:
  $$\frac{\partial \text{Accuracy}_{\text{grep}}}{\partial \text{Noise Volume}} \approx 0$$

## 5. Capacity-Constrained Incremental Summarization & Compaction (The MaxIM Invariant)

> **Pattern Origin**: Absorbed from Google Research / Google DeepMind (*"MaxIM: Maximally Informative Incremental Summarization via Reinforcement Learning"*, NeurIPS 2026, arXiv:2611.12825).

Mathematical formulation of memory compaction and incremental summary updating under hard context constraints:

### A. The Capacity-Constrained Memory Problem
Let $H_t = (O_1, a_1, r_1, \dots, O_t)$ denote the full interaction history up to turn $t$, and let $S_t \in \mathcal{S}$ denote the incremental memory summary constrained by token budget $C$ ($|S_t| \le C$).
At each step transition $t-1 \to t$, the summary updates:
$$S_t \sim \pi(S_{t-1}, O_t)$$

### B. Dual Information-Theoretic Bounds
To guarantee optimal sequential decision-making without narrative hallucination, the summarization policy $\pi$ must satisfy two orthogonal bounds:

1. **Predictive Sufficiency (Forward-Facing Bound)**:
   - Maximizes mutual information between the summary $S_t$ and future task-critical targets $Y_{\ge t}$ (unfulfilled acceptance criteria, pending tool parameters, downstream interfaces):
     $$\max_{\pi} I(S_t; Y_{\ge t} \mid S_{t-1}) \iff \max_{\pi} \mathbb{E}\left[\sum_{\tau \ge t} \log p(y_\tau \mid S_t)\right]$$
   - Directly minimizes downstream **Value Suboptimality** ($\Delta V = V^*(H_t) - V^*(S_t)$). Historical details with zero predictive utility for future turns are discarded.

2. **Recursive Consistency (Backward-Facing Anti-Hallucination Bound)**:
   - Maximizes mutual information between the summary $S_t$ and observed trajectory $H_t$:
     $$\max_{\pi} I(S_t; H_t \mid S_{t-1})$$
   - Prohibits the agent from fabricating speculative assertions. Every factual token in $S_t$ must be entailed by physical tool execution logs, exit codes, and verifiable file paths:
     $$\text{Entailment}(S_t, H_t) = 1.0$$

### C. Step-Wise Verification Density
Rather than evaluating summarization quality only at the end of an episode (sparse reward), the agent asserts retention quality at **every turn transition**:
- Retain exact error traces, exit codes, and contract signatures until resolved.
- Once a contract is fulfilled and verified, prune intermediate trial-and-error reasoning while preserving the resulting immutable state hash.

## 6. Relative Preference & Policy Alignment Metrics (TRL / DPO & GRPO Heuristics)

> **Pattern Origin**: Absorbed comparative evaluation heuristics from `huggingface/trl` (§8 External Proposal Protocol).

Evaluation metrics for ranking multi-candidate agent rollouts, code generation variants ($k \ge 2$), and multi-agent debate outputs:

### A. Direct Preference Optimization (DPO) Scoring Margin
When comparing two candidate agent outputs $y_w$ (preferred/winner) and $y_l$ (dispreferred/loser) for a prompt $x$, the implicit reward differential under DPO is modeled as:
$$\Delta r(x, y_w, y_l) = \beta \log \frac{\pi_\theta(y_w \mid x)}{\pi_{\text{ref}}(y_w \mid x)} - \beta \log \frac{\pi_\theta(y_l \mid x)}{\pi_{\text{ref}}(y_l \mid x)}$$

In an inference-time evaluation harness without a reference model, this translates to the **Deterministic Bradley-Terry Margin**:
$$P(y_w \succ y_l \mid x) = \sigma\left(\text{Score}(y_w) - \text{Score}(y_l)\right) = \frac{1}{1 + e^{-(\text{Score}(y_w) - \text{Score}(y_l))}}$$
- **Production Assertion**: A code candidate $y_w$ is declared superior only if $\text{Score}(y_w) - \text{Score}(y_l) \ge \delta_{\text{margin}}$ across $\ge 2$ orthogonal rubrics (correctness, efficiency, safety). Tie scores default to the shorter diff (MVBR invariant).

### B. Group Relative Policy Optimization (GRPO) Candidate Evaluation
Instead of relying on absolute point-scores from LLM judges (which suffer from prompt calibration drift), GRPO normalizes reward values across a group of $G$ sampled completions $\{y_1, y_2, \dots, y_G\}$ for prompt $x$:
$$A_i = \frac{R(y_i) - \mu_R}{\sigma_R + \epsilon}$$
Where:
- $\mu_R = \frac{1}{G} \sum_{j=1}^{G} R(y_j)$ is the empirical group mean.
- $\sigma_R = \sqrt{\frac{1}{G} \sum_{j=1}^{G} (R(y_j) - \mu_R)^2}$ is the standard deviation.
- $\epsilon = 10^{-6}$ prevents division by zero.

### C. Harness Integration Protocol for Pass@k Trials
1. **Zero-Baseline Elimination**: When $k > 1$ candidate solutions pass basic syntax checks, compute group advantage $A_i$ across test execution speed, cyclomatic complexity, and diff size.
2. **Selection Invariant**: Automatically promote the candidate with $A_i \ge +1.0\sigma$. Discard candidates with $A_i < 0$ without presenting intermediate trials to user context.
