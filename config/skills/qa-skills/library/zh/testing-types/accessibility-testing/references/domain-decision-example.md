# 领域判定示例

此脱敏合成 fixture 用于校准本 Skill 的分析，不是项目真实执行或业务验收记录；数值和协议仅适用于本示例。

## 输入

项目目标 WCAG 2.2 AA，仅结账弹窗。证据 S-1：自动扫描零发现。证据 K-1：键盘可以打开弹窗，但 Tab 无法到达“确认付款”按钮，项目指定对应 2.1.1。证据 K-2：关闭弹窗后焦点返回原触发按钮，指定 2.4.3。R-1：读屏尚未执行。逐项判定 SCAN_CLEAR/FAIL/PASS/NOT_RUN，列准则 ID 和证据类型，不作全站合规结论。

## 逐项预期

| ID | DECISION |
| --- | --- |
| S-1 | SCAN_CLEAR |
| K-1 | FAIL |
| K-2 | PASS |
| R-1 | NOT_RUN |

## 核对方法

1. 记录项目指定的 WCAG 版本/等级、范围和成功标准 ID；目标未指定时列为缺口，不能自行选等级或声称合规。
2. 建立 成功标准 ID | 用户任务/状态 | 输入方式/辅助技术/版本 | 检查步骤 | 证据类型 | 结果 表。自动扫描、键盘操作、读屏和人工视觉检查分别记录。
3. 键盘检查实际完成导航、打开、操作、关闭并检查焦点去向；读屏检查名称/角色/状态与动态更新。不可达的关键操作按用户任务影响优先。
4. 扫描零发现只能表示扫描范围内未发现；人工失败保留 FAIL，未执行项目保留 NOT_RUN。按准则汇总证据，不将局部扫描升级为整体合规。
