# 领域判定示例

此脱敏合成 fixture 用于校准本 Skill 的分析，不是项目真实执行或业务验收记录；数值和协议仅适用于本示例。

## 输入

协议 R-v2：相同 operation_id 只能产生一条扣账；可查询后重试未提交步骤；权限永久错误必须停止并升级。F-1 trace：op=pay-1 扣账已提交，响应超时；重试又扣账，同 op 两条。F-2：三步任务前两步已提交，恢复仅执行第三步，最终三步各一条。F-3：403 permanent 后连续重试五次。给每条 trace PASS/FAIL，并给应走分支、恢复后状态及证据。

## 逐项预期

| ID | DECISION |
| --- | --- |
| F-1 | FAIL |
| F-2 | PASS |
| F-3 | FAIL |

## 核对方法

1. 按项目协议建立 故障 | 写入是否确认 | 可重试性 | 重试/补偿/升级 | 恢复后状态 | 所需证据 表；暂时错误、永久错误和结果不确定分开。
2. 超时不能推出未执行：先以 operation_id/幂等键查已提交副作用，再决定读回结果或安全重试；同键不得产生第二次业务写入。
3. 部分成功按已完成步骤和剩余步骤核对；补偿仅在协议和授权允许时执行，逐步记录补偿结果，失败进入升级。
4. 永久错误停止原样重试并通知责任人。核对恢复前后业务状态、重试次数、用户可见结果与资源；缺日志时恢复仍待验证。
