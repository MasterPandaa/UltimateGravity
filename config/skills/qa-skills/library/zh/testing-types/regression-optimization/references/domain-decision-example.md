# 领域判定示例

此脱敏合成 fixture 用于校准本 Skill 的分析，不是项目真实执行或业务验收记录；数值和协议仅适用于本示例。

## 输入

相同版本/环境/义务：基线顺序10分钟，重复退款故障使T-refund失败。O-1隔离后并行6分钟，同故障仍失败且无数据冲突。O-2删T-refund变4分钟，故障全绿。O-3换了不同规模项目3分钟却宣称提速70%。O-4关键义务映射缺失。用ACCEPT/REJECT/NOT_COMPARABLE/UNKNOWN，给收益比例、保护约束和解除缺口条件。

## 核对方法

1. 固定before/after变更版本、环境、测试义务集合、数据和窗口；列选择/排序/并行/缓存候选的纳入与排除证据，不比较不同规模总时长。
2. 将关键风险/已知逃逸/必须门禁作为保护约束；删去唯一保护的提速不得采纳，未知映射保留保守验证或升级。
3. 分别度量耗时/资源、故障检出、漏检/逃逸与不稳定；相同可控故障在候选中仍需被原义务的有效断言检出，绿灯不证明保护保留。
4. 给收益条件、残余风险、实施/回滚触发与责任人；取舍涉及移除保护须由有权人接受，不能以优化建议代替授权。
