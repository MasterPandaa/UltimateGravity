# 领域判定示例

此脱敏合成 fixture 用于校准本 Skill 的分析，不是项目真实执行或业务验收记录；数值和协议仅适用于本示例。

## 输入

项目已用 Playwright。候选 C-1：稳定登录，隔离账号，oracle=会话主体与账户页一致，每日执行，清理可注销。C-2：每日变化原型，缺状态 oracle。C-3：高收益付款流程只连生产真扣款、无授权沙箱/清理。C-4：已有结账测试只断言页面标题，付款失败仍标题正常。逐项 ADOPT/DEFER/REPAIR，不因收益高换框架或直接压生产，明确投入门槛与业务断言。

## 逐项预期

| ID | DECISION |
| --- | --- |

| C-2 | DEFER |
| C-3 | DEFER |
| C-4 | REPAIR |

## 核对方法

1. 用 候选流程 | 保护义务 | 重复频率证据 | oracle/可观测性 | 数据隔离/清理 | 稳定性 | 维护约束 | 采用/延期理由 表选型；ROI 另列成本情景，不能抵消缺 oracle 或无授权环境。
2. 优先沿用现有框架；先检查是否有可核对后置条件、可独立数据和可传播失败的 CI 入口，不满足者延期并写解除条件。
3. 执行场景包含唯一账号/业务键、前置状态、动作、业务后置条件、失败信号和 teardown；失败必须让 runner/CI 失败，不能仅记录日志。
4. 区分自动化候选、生成资产、真实运行与业务验收；频繁变化的原型或无法隔离的真实扣款保留人工/受控验证候选，取舍由风险和证据说明。
