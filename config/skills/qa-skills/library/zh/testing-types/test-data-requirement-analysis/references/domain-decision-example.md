# 领域判定示例

此脱敏合成 fixture 用于校准本 Skill 的分析，不是项目真实执行或业务验收记录；数值和协议仅适用于本示例。

## 输入

场景S1：3个并行worker每个独立paid Order及同属该订单Refund，禁止共享。S2：计划退款场景但未给schema/字段。S3：要真实客户邮箱，未提供允许获取或脱敏授权。S4：相同订单重试2次，必须复用同refund_id而不是造两个业务键。用S1 SPECIFIED、S2 UNKNOWN、S3 BLOCKED、S4 SPECIFIED，说明实体关系/数量依据，不实际生成或取得真实资料。

## 逐项预期

| ID | DECISION |
| --- | --- |
| S1 | SPECIFIED |

## 核对方法

1. 从场景/风险列场景→实体/状态/关系→取值/边界→数量依据→获取来源/权限→准备/清理条件矩阵；本Skill分析需求，不默认生成或抓取数据。
2. 数据量依据来自并发/隔离/重复次数/消耗模式，未知次数给公式与缺口；不能自定100行或把会话数等同实体数。
3. 缺schema时分开已知业务关系与未定义字段/键，提出最小澄清；跨实体状态和外键需求必须可追踪，不仅列CSV文件名。
4. 个人/受限数据优先合成或许可脱敏，记录来源限制、保留/清理、验收oracle；授权未知标BLOCKED，不把分析建议写成已准备完成。
