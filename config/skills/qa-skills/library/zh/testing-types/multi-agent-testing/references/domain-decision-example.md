# 领域判定示例

此脱敏合成 fixture 用于校准本 Skill 的分析，不是项目真实执行或业务验收记录；数值和协议仅适用于本示例。

## 输入

协议 Team-v1：每任务一owner，同task_id提交一次；只接收当前共享版本，失败任务必须有重派或明确升级。A-1 taskT被workerW1与W2同时认领并各写一条。A-2 共享v3，收到v2旧委派后拒绝且无副作用。A-3 子任务失败后主任务completed，未完成任务无人接管也未升级。A-4 W1提交后重复消息重投，查taskT已完成并ACK，不再写。逐项 PASS/FAIL，列消息、所有权、版本与交接证据。

## 逐项预期

| ID | DECISION |
| --- | --- |
| A-1 | FAIL |
| A-2 | PASS |
| A-3 | FAIL |
| A-4 | PASS |

## 核对方法

1. 用 task/message/correlation ID、sender/receiver、父委派、scope、owner、共享状态版本和 ACK 建立交接轨迹；按真实协议指定接收/拒绝/终止条件。
2. 认领/提交须依据项目原子所有权或fencing协议，陈旧消息与重复消息不能重新取得所有权或重复写入；未给 exactly-once 协议不假定存在。
3. 部分失败分别记录已完成、未完成和不确定副作用，重派前核对 committed 状态；任务不因一个子任务失败或超时而静默丢失。
4. 终止传播核对停止 ACK、终态与剩余责任，租约失效者不得继续提交；对照正常单一认领和有效交接，避免把消息重投本身当故障。
