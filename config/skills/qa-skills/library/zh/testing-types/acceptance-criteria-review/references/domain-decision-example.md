# 领域判定示例

此脱敏合成 fixture 用于校准本 Skill 的分析，不是项目真实执行或业务验收记录；数值和协议仅适用于本示例。

## 输入

版本 v3，原 AC-7：订单金额 >= 100 元免运费；100 元订单仍被收 5 元运费。AC-8：相同 refund_id 重试不得重复扣账；退款 20 元成功后同 ID 重试，累计退款变成 40 元。AC-9：金额 < 100 元运费 5 元，99 元实收运费 5 元。AC-10：写着“及时退款”，没有时限或观测起止点。
请逐项核对，保留原 AC ID 和原文，建议改写独立列出；判定值使用 FAIL/PASS/MISSING_RULE，并说明等于阈值与重复请求的可观察预期。

## 逐项预期

| ID | DECISION |
| --- | --- |
| AC-7 | FAIL |
| AC-8 | FAIL |
| AC-9 | PASS |
| AC-10 | MISSING_RULE |

## 核对方法

1. 先选择 `review`（核对原标准）、`proposed-rewrite`（建议改写）或 `missing-rule`（规则缺失）；保留原 AC ID、版本、原文和来源，不把建议覆盖成原规则。
2. 逐条输出：AC ID | 原标准 | 模式 | 可观察预期 | 建议文本 | 差异原因 | 待产品确认。无规则的格子保持待确认。
3. 对比较符按原文拆出小于、等于、大于三个输入；对重复请求记录业务键、累计退款、剩余可退额和最终状态。响应成功不等于账务正确。
4. 建议改写应包含 Given/When/Then、可观察数据与错误路径；确认充分的原标准标为可测试，不为凑问题制造歧义。
