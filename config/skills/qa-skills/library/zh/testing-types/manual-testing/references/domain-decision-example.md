# 领域判定示例

此脱敏合成 fixture 用于校准本 Skill 的分析，不是项目真实执行或业务验收记录；数值和协议仅适用于本示例。

## 输入

20分钟退款 charter，订单 O1 可恢复；规则同refund_id只退20元一次。M-1 已执行两次提交，账务累计40元，证据E1。M-2 已执行正常查看订单，显示金额正确，证据E2。M-3 原计划弱网重试尚未开始。M-4 执行中测试环境断开，未能读回状态。清理记录O1已恢复原始金额，证据E3。判 M-1 FAIL/M-2 PASS/M-3 NOT_RUN/M-4 BLOCKED 或据材料选择枚举，提交具体步骤、charter与未完成项。

## 逐项预期

| ID | DECISION |
| --- | --- |
| M-1 | FAIL |
| M-2 | PASS |
| M-3 | NOT_RUN |
| M-4 | BLOCKED |

## 核对方法

1. 为每个时间盒建立 charter：任务/风险、环境/构建、数据、探索范围、截止和证据；执行既定路径与探索新问题分别记账，不自行扩展授权。
2. 步骤记录 前置状态→动作→预期→实际→证据 ID→状态；未启动为 NOT_RUN，中断为 INCOMPLETE，环境阻断为 BLOCKED，不把清单当完成记录。
3. 先准备可恢复数据与检查点，结束按项目规则恢复账户、订单和配置并核对残留；未授权删除不能当清理捷径。
4. 时间不足先完成关键风险闭环并保存未完成项、负责人和恢复入口；报告只覆盖真实观察，未知预期仍待确认。
