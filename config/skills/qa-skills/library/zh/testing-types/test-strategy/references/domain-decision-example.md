# 领域判定示例

此脱敏合成 fixture 用于校准本 Skill 的分析，不是项目真实执行或业务验收记录；数值和协议仅适用于本示例。

## 输入

项目门槛：退款幂等和跨租户隔离两个义务必须有独立断言执行证据；每个需20min，有隔离环境/Playwright/API资产。C1 QA-A窗口45min可顺序完成两个。C2 QA-A窗口25min，尚无风险接受授权。C3只有用例计划无运行，却写已通过。C4未给其他通过率门槛却套95%。用FEASIBLE/ESCALATE/NOT_RUN/UNKNOWN，交付义务/负责人/深度/证据最小表，不隐藏容量取舍。

## 逐项预期

| ID | DECISION |
| --- | --- |
| C1 | FEASIBLE |
| C2 | ESCALATE |
| C3 | NOT_RUN |
| C4 | UNKNOWN |

## 核对方法

1. 以版本/业务目标与风险建立最小执行表：目标→义务/范围→层与深度→数据/环境→资源/负责人→准入准出来源→证据与剩余风险，避免分散章节无法执行。
2. 沿用项目工具与现实容量，先覆盖关键资损/授权等最低保护；每场景有业务后置条件和证据，资源不足列不可完成项与最小替代验证。
3. 准入准出值仅取项目规则，缺门槛保持待确认/UNKNOWN，不自动套95%通过率或P0数值；Human决定风险接受，不由策略草稿代替。
4. 区分设计、计划、实际运行和业务验收；给依赖/环境阻塞、范围变化、停止/重审触发与交付责任，策略能由另一执行者直接接手。
