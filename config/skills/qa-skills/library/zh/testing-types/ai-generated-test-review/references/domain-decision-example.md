# 领域判定示例

此脱敏合成 fixture 用于校准本 Skill 的分析，不是项目真实执行或业务验收记录；数值和协议仅适用于本示例。

## 输入

根据以下完整契约和代码摘要分类，不按语法报假阳性。T-1：真实 price(total, taxClient) 调用；只 mock 外部 taxClient 返回 2；独立断言 price(10)=12，错误忽略税会失败。T-2：真实 serializeOrder 生成 {id,status,total}，人工审核快照保留所有业务字段；把 paid 改为 pending 会失败。T-3：/health 唯一契约是依赖不可用时 503，没有响应体或写入义务；真实 handler 注入断开依赖断言 503。T-4：直接 mock 被测 price 返回 12，再断言 12，生产 price 从未调用。每项 STRONG/WEAK/FAKE，给具体变异理由。

## 逐项预期

| ID | DECISION |
| --- | --- |
| T-1 | STRONG |
| T-2 | STRONG |
| T-3 | STRONG |

## 核对方法

1. 按所验证的契约判断断言，不能仅因出现 mock、snapshot 或状态码就标为 WEAK/FAKE。
2. 边界 mock 可替代已确认的外部依赖，但被测生产逻辑必须真实执行；mock 被测对象并断言它返回的预设值才缺乏保护。
3. 快照需基于独立审核的业务结构、稳定字段且错误结果会产生差异；忽略所有业务字段的快照无保护。状态码足以完整表达所给契约时可为 STRONG；持久化义务存在则需追加业务后置条件。
4. 每个分类给具体可逃逸缺陷或会被检出的变异，以及契约来源；证据不足保留置信度和缺口，中英文采用同一分类理由。
