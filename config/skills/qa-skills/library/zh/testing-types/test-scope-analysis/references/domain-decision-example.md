# 领域判定示例

此脱敏合成 fixture 用于校准本 Skill 的分析，不是项目真实执行或业务验收记录；数值和协议仅适用于本示例。

## 输入

新功能v2退款：范围已确认web/API与paid订单；native明确排除；guest是否退款未定义。S1 web/API paid路径；S2 native；S3 guest边界；S4生产真扣款验证没有授权但关键义务需隔离验证。用S1 INCLUDE/S2 EXCLUDE/S3 UNKNOWN/S4 BLOCKED，列版本/层/平台/数据状态单元和新规则到达后的重审触发，不把新功能全部当回归范围。

## 逐项预期

| ID | DECISION |
| --- | --- |
| S1 | INCLUDE |
| S2 | EXCLUDE |
| S3 | UNKNOWN |
| S4 | BLOCKED |

## 核对方法

1. 从当前交付目标与版本建立版本×测试层×平台×数据状态的范围单元，关联需求/义务、纳入/排除证据、负责人和可观察验收；新需求测试不限于回归变更。
2. 分列INCLUDE、EXCLUDE、UNKNOWN，排除必须有范围来源/独立契约理由；不明支持平台、边界或数据规则保持未知，不能默认不测。
3. 预算/环境/权限限制单列BLOCKED与残余风险，关键义务不足升级，不自行替产品定义缺失边界或授权风险接受。
4. 需求/平台/接口/版本变化触发重审范围并更新单元；选取/设计、实际执行与满足状态分别报告，不把清单当覆盖证据。
