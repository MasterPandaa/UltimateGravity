# 领域判定示例

此脱敏合成 fixture 用于校准本 Skill 的分析，不是项目真实执行或业务验收记录；数值和协议仅适用于本示例。

## 输入

项目策略 M-v3：严格租户隔离；同用户最高有效版本生效；删除确认后立即不得检索。M-1：租户 A 问偏好，检索到 B/m9。M-2：A/m1 v1=短信，v2=邮件，均有效，回答仍用 v1。M-3：A/m2 删除已确认，索引仍返回 m2。M-4：A 检索自己的有效 m3 v2，未出现 B 记录。M-5：希望判定备份到期，但未给备份保留策略。逐项 FAIL/PASS/UNKNOWN。

## 逐项预期

| ID | DECISION |
| --- | --- |
| M-1 | FAIL |
| M-2 | FAIL |
| M-3 | FAIL |
| M-4 | PASS |
| M-5 | UNKNOWN |

## 核对方法

1. 为记忆记录 tenant/user ID、memory ID、内容版本、来源、写入时间、有效期、撤回/删除状态；检索结果保留来源版本，不只检查最终回答。
2. 先依据项目优先级规则选择新旧偏好；冲突未定义时标为待确认，不能默认最后写入或自定保留期。
3. 两租户同查询分别核对可见集合；版本更新后检索过时内容、到期后返回和删除后仍返回按项目一致性窗口判定。
4. 删除检查索引、缓存与备份等实际范围；未提供删除传播/备份保留协议时只报告已验证部分。正常允许检索作为隔离检查的对照。
