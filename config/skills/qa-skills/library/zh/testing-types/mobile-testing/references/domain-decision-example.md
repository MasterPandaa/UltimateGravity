# 领域判定示例

此脱敏合成 fixture 用于校准本 Skill 的分析，不是项目真实执行或业务验收记录；数值和协议仅适用于本示例。

## 输入

支持矩阵只给Android14设备D1、iOS17设备D2；deeplink规则原始coupon=A%2BB解码一次为A+B。B-1 D1冷启动丢coupon。B-2 D2热启动coupon=A+B，路由及权限正确。B-3 支付op7已扣20元后切后台，恢复重试又扣20元。B-4 恢复先查op7，UI显示已支付20元，账务仅一条。B-5 想声称Android15已通过却未执行。逐项 FAIL/PASS/NOT_RUN，保留原URI、持久状态与矩阵缺口。

## 逐项预期

| ID | DECISION |
| --- | --- |
| B-1 | FAIL |
| B-2 | PASS |
| B-3 | FAIL |
| B-4 | PASS |
| B-5 | NOT_RUN |

## 核对方法

1. 用生产分布、变化和事故证据选 OS×设备×安装/升级路径×网络×前后台 的风险矩阵，注明样本与未覆盖组合，不能臆造支持列表。
2. deeplink 保留原始 URI、解码规则、路由/参数与授权状态；比较冷启动、热启动和恢复，参数不能在恢复后丢失或二次解码。
3. 中断支付记录订单/operation_id 与提交点，恢复后服务端读回账务与 UI 状态一致；响应丢失先查状态，不能重复付款。
4. 验证升级的数据兼容、权限变化、进程终止后状态和资源；未执行设备只能作为候选，支持范围结论与真实设备证据分开。
