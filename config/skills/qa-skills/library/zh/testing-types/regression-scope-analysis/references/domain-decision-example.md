# 领域判定示例

此脱敏合成 fixture 用于校准本 Skill 的分析，不是项目真实执行或业务验收记录；数值和协议仅适用于本示例。

## 输入

金额组件变更，E1退款义务经共享类型直接依赖；E2发票经退款消费者间接依赖；E3动态税务plugin未知；E4独立图片服务无依赖。窗口仅够一个测试，项目要求退款与发票均为必须保护，尚无人接受缺口。判E1/E2 INCLUDE、E3 UNKNOWN、E4 EXCLUDE，窗口不足项BUDGET ESCALATE；不得静默只跑退款并说范围足够。

## 核对方法

1. 以变更和当前基线为入口，列变更→受影响义务→测试层/平台/数据状态→纳入/排除及证据的矩阵；回归保护已有行为，不把新特性完整测试混为回归。
2. 检查直接、传递与动态依赖、历史逃逸和非功能影响；未知依赖单列，不以无映射当无影响，排除需契约/证据证明。
3. 预算不足时保留最低关键义务和风险余量，给不可覆盖项、最小替代证据、负责人及授权接受/升级条件，不静默裁掉高风险。
4. 输出候选范围、顺序、资源、触发追加范围的信号；已选测试、已执行和已满足分别记，不能用计划数替代通过证据。
