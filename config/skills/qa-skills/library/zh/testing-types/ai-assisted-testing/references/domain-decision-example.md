# 领域判定示例

此脱敏合成 fixture 用于校准本 Skill 的分析，不是项目真实执行或业务验收记录；数值和协议仅适用于本示例。

## 输入

相同 10 个结账用例：人工基线 60 分钟。AI 生成 10、复核 25、返工 35、验收 10 分钟。I-1：输入已脱敏，draft D1 的断言经 QA R1 核对，采纳 V2 实际执行且验收 10/10。I-2：D2 未经人工复核却标已采纳。I-3：团队以生成 10 分钟宣称总耗时下降。判断 I-1/I-2 用 ACCEPTED/DRAFT，I-3 用 UNSUPPORTED/SUPPORTED，给总工时及来源链。

## 核对方法

1. 先记录输入分类/脱敏方法与允许使用范围；真实身份、令牌和个人数据替换为不可反推占位符，保留 schema 与业务约束。
2. 建立 输入快照 ID→模型/Prompt 版本→AI 草稿 ID→人工复核意见→采纳版本 ID→验收证据 来源链；草稿不自动成为执行资产。
3. 标明谁核对业务 oracle、断言、隐私与高风险取舍；未复核产物保持 draft，未实际执行保持 NOT_RUN，AI 不代替 Human 接受。
4. 用相同任务、复杂度与窗口测量人工基线工时，以及 AI 生成+复核+返工+验收总工时；分别记录质量缺陷与返工数量，不能只以生成耗时宣称提效。
